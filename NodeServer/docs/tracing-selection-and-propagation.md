# 追踪位置选择与输入门控

本轮规则保留装箱、Proxy、AST 和迭代重放。分析范围依据同目录的 JS 表达式/语句研究。

## 1. 选取位置

从堆栈匹配已执行脚本版本，定位最深 AST 节点，再沿当前执行函数内部的父链上行。传播位置与 statement 上下文独立收集，不能在遇到第一个 expression 时丢失 statement。

- `let a = b + c++`：c 的事件对应 update 和 a 的初始化两个候选；b 的事件对应 a 的初始化。重写初始化时也必须保留其中 update 的独立语义。
- `if ((x = data.n + 1) > 3)`：记录 x 的赋值和 test 条件使用。
- `if (ok) { const x = data.n + 1; }`：记录初始化，外层 if 只作为上下文，data.n 不成为条件来源。
- 已改写的表达式不重复处理；其中延后执行的回调体不是已覆盖区域。

## 2. 候选与用途

声明初始化、赋值、update、return/throw、调用/构造/带标签模板和默认导出表达式是候选位置。条件、switch 判别式/实际 case.test、for 的 init/test/update、for-in/of、成员 base/key 等分别记录用途。

独立且结果丢弃的计算不是补代理候选；不删除原计算，也不忽略其中调用和写入。块、函数定义等容器不整体收集来源。没有值操作数的 break/continue/empty/debugger 不补代理。

## 3. 传播约束

传播只能由本次实际输入的代理元数据触发，不以“执行过程中某处读到了来源”作为全部返回值的来源。保留一次求值、短路、接收者和引用语义。

对象属性与数组元素分别保留来源，容器可以代理但不把合并来源下发给所有子属性。未知函数的返回对象、原生操作和异步载体需要明确摘要或缺口，不能自动认为所有成员均有来源。

本文件随实现与验证更新，支持细节及最终证据在完成本轮回归后补充。
